# BM25

Implemented in `retrieval/bm25.py` as Okapi BM25 with the Robertson/Zaragoza formulation.

```
idf(t) = log((N - df(t) + 0.5)/(df(t) + 0.5) + 1)          # smoothed, always ≥ 0
score(D, Q) = Σ idf(t) · tf(t,D)·(k1+1) / (tf(t,D) + k1·(1 - b + b·|D|/avgdl))
```

- `k1` (default 1.2), `b` (default 0.75) are constructor arguments; invalid values raise `ValueError`.
- `score_terms` dedupes query terms (repeated terms do not double-count).
- Missing terms are skipped; zero-score hits are omitted.
- Ranking is deterministic: `(-score, doc_id)`.

Tests under `test_bm25.py` verify the formula by hand against known `dl`, `avgdl`, `df`, `N`.

## Ranking Pipeline

`ranking/pipeline.py`:

- `RankingSignal` subclasses `ExactTitleSignal`, `UrlRelevanceSignal`, `FreshnessSignal`, `QualitySignal`. Each returns `SignalScore(name, value ∈ [0,1])`.
- `RankingConfig` weights (`bm25_weight`, `title_weight`, etc.) and toggles (`enable_title`, ...). `balanced()` and `bm25_only()` presets.
- `RankingPipeline.rank(query, index, limit, offset)` computes BM25, evaluates enabled signals, produces `RankedHit(final_score, bm25_score, signals)` and sorts by `final_score`. `hit.explanation()` is the dict shown in `ResultList`'s "Why this result?" disclosure.

The HTML thread ties ranking explanations into the frontend: see `ResultList.tsx`.
